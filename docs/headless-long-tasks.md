# Headless long tasks and trusted acceptance

These mechanisms support testing long tasks; they are not proof that a build has completed a real six-hour evaluation. Network recovery, tool completion, product quality and uninterrupted runtime are separate measurements.

## Optional budgets and recovery

`METIS_RUN_MAX_SECONDS` and `METIS_TURN_MAX_SECONDS` are unlimited when absent, empty or `0`. Positive values impose explicit budgets. Parent cancellation remains authoritative. Individual tools and HTTP requests retain their own limits.

Transient recovery is opt-in. A recommended evaluation policy is:

```text
METIS_RECOVERY_MAX_SECONDS=600
METIS_RECOVERY_MAX_ATTEMPTS=30
METIS_RECOVERY_MAX_BACKOFF_SECONDS=30
```

The window begins at the first transient failure of a logical response. Responses/Codex HTTP attempts, SSE restarts and previous-response fallback share that window and attempt counter. Complete tool calls from an interrupted response are not executed. Already executed tools are not replayed. A final failed draft retains only plain text for auditing, not incomplete tool arguments or provider state. Successful responses begin a new logical-response budget. Normal active streams are not cancelled merely because a past recovery window's timer expires; ordinary request and parent deadlines still apply.

Permanent HTTP 400/401/403 and cancellation do not enter long recovery. With recovery disabled, existing short retry behavior is retained. Other providers' SDK retries are unchanged, so their outer `Stream` attempt count is not a strict count of underlying HTTP requests. See `internal/llm/transport/README.md` for details.

## Host-owned machine verification

This is an optional, currently benchmark-specific browser integration. It is not a general-purpose browser, CDP interface or global sandbox exception. The trusted broker must be provisioned separately; Metis does not create its VM or containers.

Trusted process startup settings:

```text
METIS_VERIFICATION_URL=http://127.0.0.1:<BROKER_PORT>
METIS_VERIFICATION_TOKEN=<RANDOM_URL_SAFE_TOKEN_32_TO_256_CHARACTERS>
METIS_VERIFICATION_REQUIRED_CHECKS=build,typecheck,smoke,controls,endurance
```

Never put the token in a task prompt, source tree, command argument, transcript or public artifact. `METIS_*` is stripped from credential-isolated Bash environments; do not enable secret inheritance for this benchmark. The broker must run outside the model-writable product directory. Its endpoint is loopback-only, with no proxy or redirect. Tool arguments cannot choose an endpoint, path, URL, script or command.

`BrowserTest` runs only `smoke`, `controls` or `endurance` and waits for terminal results. Each call has a 35-minute outer bound covering dependency preparation, the finite suite and cleanup; an earlier parent deadline wins. There is no HTTP-fetch substitute for real browser evidence. `TaskClock` reports live UTC and the current invocation's monotonic elapsed time; a resumed process restarts that elapsed clock. It does not pretend to measure effective work. Startup environment dates are explicitly marked as snapshots.

The effective allowlist and permissions must permit the fixed tool. Excluding it causes `environment_blocked`, not a silent downgrade. A headless check can be run before spending model tokens:

```sh
metis run --bare --no-auth-wizard --mode bypassPermissions \
  --provider openai-codex --model gpt-5.5 \
  --tools Read,Write,Edit,Bash,BashList,BashOutput,BashKill,Grep,Glob,TodoWrite,BrowserTest,TaskClock \
  --preflight-only
```

This validates runtime/configuration, pre-authorized tools and broker source hashing. It reports effective tool names, required checks and the source SHA-256 as JSON, and never starts the task model loop or automatic memory extraction. Runtime setup may still access existing authentication/session state; it is not a completely side-effect-free dry run. It does not itself launch Chromium or establish that WebGL, controls, endurance or physics pass. Those require actual fixed suites.

At completion, evidence is fetched from the trusted broker, not model-authored files. Every required check must have a unique ID, PASS status, exit code zero, nonnegative duration and a valid nonempty artifact SHA-256. The source hash must match before and after verification. An `endurance` check additionally requires at least 900,000 ms. All required suites must be rerun after product source changes. Response caching is disabled when verification is enabled.

Missing, failed, stale or malformed evidence never becomes success through an `OVERRIDE CONTRACT`. The loop allows bounded corrective re-entry. `ACCEPTANCE_INCOMPLETE:` explicitly reports inability to finish; incomplete/environment-blocked results use exit code 11. A broker infrastructure error is not automatically blamed on product code.

The ABYSS benchmark also registers a separate `physics` check, generated by a fixed independent grader in the controls suite. Browser telemetry alone is not evidence that collisions or 3800 m reachability are correct. Public deployment needs a separate source review and final independent acceptance.

## Required finite Bash jobs

Long-running finite checks may use:

```json
{"command":"npm run test:endurance","run_in_background":true,"await_completion":true,"required_for_completion":true}
```

`required_for_completion` implies `await_completion`. Starting and registering a finite job is atomic with Run cleanup, including cancellation before a tool result arrives. Required jobs must actually terminate successfully before completion. Nonzero, killed or missing required jobs leave acceptance incomplete. The policy is conservative: a later successful job does not erase an earlier required failure in the same Run. Default background dev servers do not block completion and are not silently converted to finite jobs.

## Honest evaluation accounting

Keep three-hour/six-hour wall time, longest single process, external continuations, recovery wait, browser endurance, product acceptance and artifact collection separate. A fast completed task does not prove six-hour reliability. A six-hour idle process does not prove useful autonomous work. Unit tests with virtual time do not replace real elapsed-time tests. Preserve failed attempts; do not repair their products and relabel them as autonomous passes.
