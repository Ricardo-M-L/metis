# Desktop 模型设置

Desktop 原生窗口与 `metis desktop --web` 共用模型设置页面。

提供商列表只显示已添加或已有配置的连接，不预置 Anthropic、OpenAI、Codex、Gemini 四个空占位。连接预设在“添加提供商”时选择，也可以手动填写；已添加但尚未填写密钥的连接仍会保留。

列表只显示名称、凭据状态、已配置模型数量及默认/当前标记。进入编辑页后配置连接、密钥和多个模型；较少使用的参数在高级设置中展开。凭据状态表示是否存在可用的认证配置，不表示模型推理已经通过测试。

新增提供商不能复用已有 ID；已有连接通过编辑修改。每个模型的高级设置分别保留展开状态。

已添加连接的移除权限取决于配置归属，不再区分是否为内置 ID。默认提供商须先切换默认值才能移除；环境变量或工作区管理的连接会显示无法移除的原因。移除会清理该连接的本地配置、模型设置及受管理的 API key/OAuth 凭据，刷新或重启不会恢复空占位。

## 默认选择与当前会话

- **保存提供商**只保存配置，不自动把它设为默认，也不切换现有会话。
- **设为默认**选择新会话的提供商和模型；新建会话读取最新已保存配置。
- **应用到当前会话**通过模型切换接口重建当前会话的模型运行时。运行中的任务不能被配置保存操作暗中换成另一条路由。
- 重启后保留已保存的默认选择、模型列表及每个模型的设置。

## 模型列表与能力

可以从本地模型目录、提供商模型接口导入候选，也可以手动添加模型 ID。首次安装没有目录缓存时，可显式更新公开的连接预设，也可继续手动填写。打开设置和读取本地目录不会自动联网；更新公开目录不使用模型密钥。

获取候选不会自动保存；导入只保存模型身份和名称，让能力继续自动识别。导入已有 ID 时保留手工编辑的能力声明。

模型的高级设置分别表示：

| 设置 | 含义 |
| --- | --- |
| 上下文容量 | 用户声明的模型完整容量；不是自动压缩使用的工作预算 |
| 最大输出能力 | 用户声明的输出能力上限 |
| 输出预算 | 每次请求实际允许生成的 token 上限 |
| 图片输入 | 自动识别，或显式声明支持/不支持 |
| 推理能力 | 自动识别，或显式声明支持/不支持 |
| 推理档位映射 | OpenAI Chat/Responses 路由中，`low`、`medium`、`high` 对应的 API 值 |

空白能力字段继承原有识别结果。手工声明不能突破已知的更小供应商能力上限。上下文工作预算仍通过独立的上下文预算设置管理。

推理强度的“默认”不发送手工档位覆盖。未声明的档位不能被当作有效选项使用。Anthropic 沿用其 thinking budget 映射；Gemini 不通过手工声明绕过当前协议的推理控制限制。Codex OAuth 的端点不接受公开 Responses API 的输出预算参数，因此不提供该参数的编辑。

## 密钥与保存

密钥为单向输入，已保存值不返回到浏览器。留空表示保留，替换与移除使用明确操作；取消或离开编辑页会清空密码输入。

密钥绑定提供商、协议和端点。修改端点不能把旧端点的已保存密钥自动转发到新地址。来自环境变量的凭据不能通过删除本地保存值假装已经移除。

编辑页携带配置 revision。其他窗口或进程更新后，旧草稿保存会返回冲突并要求重新载入。配置、模型列表和受管理凭据由设置存储统一保存，失败不能被显示为全部成功。

OAuth 登录仍使用 `metis login`；此页可以查看其状态和管理支持的模型选择，不把 API key 输入当作 OAuth 登录。

## 连接检查

本地验证、模型发现和真实推理是不同检查：

- 本地验证不发送模型请求。
- 模型目录可能来自本地缓存；端点发现只验证模型元数据接口。
- 真实 query 的验收需要检查实际路由、请求参数、响应及 token 回执。

开发验收脚本为 `scripts/e2e/provider_settings_live_check.py`；`--self-test` 不读取认证文件或访问网络。真实验收使用单独编译的临时 CLI、私有配置和工作目录，并在成功或失败后清理 CLI、凭据、子进程和监听端口。
