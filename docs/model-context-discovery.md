# 模型上下文能力发现

自定义接入的窗口不能由传输协议推断。Metis 在首次模型请求前向当前
provider 的同一端点读取模型目录，先尝试 `client_version=pi` 的能力响应，
必要时合并普通目录。模型 ID、默认上下文、扩展最大上下文、最大输入和最大输出分别保留。

默认工作预算自动采用有独立可靠依据的完整模型容量，并受当前接入路线明确报告的
总窗口、最大输入和最大输出约束。客户端推荐值不充当模型物理容量；缺少完整容量依据
时保留有来源的端点值或保守估计。显式工作预算可以更小，不能突破已确认的接入上限。

预算按提供商、实际协议、规范化 BaseURL、稳定账号身份和精确 wire model ID 保存，
文件为 `METIS_HOME/context-budgets.json`，默认位于 `~/.metis`。认证 Token 和 Key 不写入
预算文件。设置中的“上下文预算”可选择自动或手工窗口：保存 `0` 表示恢复自动，
而不是零容量。不同模型、端点、协议和订阅账号不共用手工预算。旧版提供商级
`context_window` 仅兼容其配置模型；其他模型使用各自的预算或自动发现。

设置保存不打断正在生成的请求。现有会话在下一次模型请求前读取新预算，并把能力、
Loop、Compactor 和状态显示绑定到同一版本；读状态和 `/ctx` 不做网络或文件刷新。
保存时携带服务端返回的路线摘要，提供商路线已经改变则拒绝旧表单，要求重新加载。
预算文件损坏或账号发生变化时在生成请求前报错，不沿用错误的旧预算继续发送。

CLI `/ctx` 和 Desktop 上下文详情分别展示当前工作预算、端点默认值、客户端推荐值、
客户端目录最大值、模型完整容量、预算允许上限、独立输入／输出限制和各自来源。
未确认的容量显示未知；手工工作预算不能作为模型容量证据。

完整 Codex 客户端模板有单独的 `client_profile` 语义：它的推荐窗口和目录最大值
不等于模型的完整容量。已知型号按精确路由或一致的精确 model ID 使用目录中的
完整 Context／Input／Output；客户端建议单独保留和显示。型号未知或目录冲突时
先尝试同一端点明确提供的模型发行者信息：原始 `owned_by` 可由同一模型 ID 或
唯一的 `display_name == slug` 目录关联补全。跨 ID 关联仅补发行者，不改变所选模型 ID，
也不借用另一 wire alias 的输入／输出额度。发行者身份注册表只保存原厂身份和受信域名，
不保存模型窗口；随后按原厂目录中的精确型号查找容量。多个原厂地域的总窗口必须一致，
输入／输出字段分别保留，不做加减推算。明确接入路由和已知第三方路由仍优先，普通端点
真实容量和独立输入／输出上限仍生效。缺少发行者、关联不唯一、原厂记录冲突或缺型号时
仍使用保守推荐值，不按型号前缀猜出百万窗口。普通目录仅有最大值时不会自动扩大当前窗口。
最大输入单独约束压缩和摘要的输入预算；它不等于总上下文，也不会与输出上限相加来伪造窗口。

已登记的发行者包括 Kimi／Moonshot 和智谱／Z.AI。智谱容量只从经过官方 API 与文档
域名校验的 `zhipuai`、`zai`、`zai-coding-plan` 精确模型记录取得；GLM-4.5、GLM-5.3
等各自读取容量，不能把一个系列统一设成百万。代理的 `client_version=pi` 响应可能克隆
GPT 客户端模板：未知模型继承的 272k 只是兼容目录回退，不是该模型的原厂上限。

关联记录的真实限制另存于 `AssocLimits`，与客户端 profile 窗口分开。普通目录明确给出
总窗口时，`capacity_window` 证据只传递总窗口；独立输入／输出字段需要该普通记录明确
声明 `limit_evidence = "served_capacity"`，保存为 `declared_served`。只有裸输入／输出数字、
未知标记、厂商冲突或不唯一的别名不会形成跨 ID 额度约束。相同 ID 的普通真实窗口也会
单独保留。运行预算受这些已验证的总窗口和独立额度限制；显式预算可在端点声明的最大
窗口内调整，不能超过已证明的物理上限。已知输出上限也受总窗口约束，未知字段仍保持未知。

请求边界会刷新已命中但过期的模型目录。并发调用共享一次最长 5 秒的目录请求，单个调用者
取消只停止自己的等待。刷新失败或仍返回过期缓存时，保留旧能力并冷却 30 秒后再尝试；
构造和状态读取不启动目录网络请求。原厂 API 域名与文档域名分别验证，Moonshot API 仅
接受 `moonshot.ai/cn`，文档另接受官方迁移后的 `kimi.ai`。

缓存按 provider、实际 BaseURL 和传输协议绑定，不保存认证字段。Schema 4
保留窗口语义、原始显示名、发行者关联及限制来源；旧 schema 1／2／3 缺少必要证据，必须重新发现
而不是直接沿用旧窗口。磁盘缓存
与配置均使用 `METIS_HOME` 指定的根目录；未设置时使用 `~/.metis`，避免配置目录与容量目录不一致。
在构造时同步加载；请求边界更新和跨进程缓存重载后，Loop、Compactor、
输入预算层级、状态和界面采用同一份能力快照。状态读取只访问内存。
显示的使用率以当前窗口为分母，最大支持值只作为额外信息展示。

端点无法提供目录时保留已验证的缓存或带来源的回退值。明确配置的目录路由
不借用别的 provider；未知 profile 只有在相同模型 ID 的目录容量一致时才能使用模型级匹配。
OpenAI Codex 订阅通过自己的 OAuth 模型目录发现能力，缓存和预算按稳定账号隔离；
访问令牌轮换不改变账号预算，账号改变则要求重新构造客户端。Native Gemini 从实际
生成路线的精确模型读取 `inputTokenLimit` 与 `outputTokenLimit`，其窗口标记为输入预算，
不重复扣除独立输出容量。Azure、Vertex、Bedrock 共用预算存储和请求边界安装流程，
但未具备发现证据的模型容量仍未知，不以手工窗口伪造自动上限。

若新能力证明配置的输出预算无效，运行在发送生成请求之前报错，不默默更改输出预算。
能力安装遇到并发压缩时，状态读取不等待；请求等待安装或按自己的上下文取消。
有效回复可以使下一轮待回放历史超过较小的手工工作预算；这种情况触发下一请求的
压缩，不会把服务端的合法用量丢弃。输入预算与总上下文按各自含义检查，能力限制
更新会使旧请求用量锚点失效，避免用上一份限制解释新状态。

本地验收使用新编译的临时 CLI 和当前选定模型的真实 query。
短 query 验证发现、绑定、恢复缓存和显示链路；超过 272k 的真实输入用于验证
不再按客户端建议提前压缩。具体实际 token 数、模型和能力来源由各轮验收报告记录，
这些测试不等于恰好填满百万窗口的极限压力测试。
测试进程、认证临时文件和临时可执行文件在每一轮结束后清理。

用量验收使用临时配置中的 `METIS_DUMP_PROMPTS` 将同一次物理请求、原始请求体 SHA256、
响应 SSE 的绝对用量快照与 CLI trace 关联。只保留模型、请求摘要、结构与用量白名单，
原始 prompt dump 随私有测试目录清理。文本摘要在脱敏前记录 SHA256、UTF-8 字节数和
有序角色／文本块结构；脱敏后的正文可能因恰好包含凭据子串而改变，不能用它证明原文
被删改或重复。可通过私有 `METIS_DUMP_TEXT_PROBES` JSON 字符串数组核对 nonce：
仅在 dump 开启时对原始 JSON 字符串值计数，保存 probe 哈希与次数，不保存 probe 正文，
最多 32 项、每项 128 字节。验收保留 nonce 与完整 payload 恰好一次、同会话历史顺序、
同一次请求的用量一致性约束。Messages 协议的输入、缓存创建、缓存读取按其
互斥字段合同计算。每个明确报告的字段采用最新绝对值，即使终态值比起始估计更小或明确
归零也覆盖旧值；省略的字段保留前一个快照。不能保留更大的旧计数，也不把不同 SSE 帧
累加或按数值接近两倍猜测扣减。验收另以最大单项
报告值作为输入下界，避免依赖字段是否重叠来证明超过 272k。后续轮次显式使用同一 session，
回忆旧校验点并核对历史顺序及实际缓存读写。该核对证明网关响应与客户端解析一致，
不替代供应商账单或最终上游请求体对账。
