# 图片上下文与附件重读

图片以原生视觉内容发送给模型。上下文计量采用有效的服务端用量，以及尚未被该用量覆盖的本地内容估算；base64 是传输编码，不按普通文本长度计入视觉 token。

## 附件引用

用户图片和工具图片使用解码后内容的 SHA-256 作为 `attachment_id`。附件保存在会话存储中，引用贯穿活跃历史和压缩检查点。

`ViewImage` 支持两种互斥输入：

```json
{"path":"/path/to/image.png"}
```

```json
{"attachment_id":"<64位十六进制附件ID>"}
```

附件 ID 读取使用当前调用所属会话的存储和授权。原始临时文件删除后，已持久化的附件仍可读取；缺失、损坏、未登记或属于其他会话的附件会报错。附件在本地保存不表示每次请求都会自动发送它。

子代理工具产生的图片通过 `image_attachment` 日志记录归属到原调用会话；这些记录不作为聊天消息发送给模型。导出、导入及会话分支需要一同保存有依据的图片引用和字节，分支不能继承其时间点之后才产生的附件。

## 压缩策略

默认不再按窗口大小固定只留最近一至三张图。需要释放上下文时，优先保留当前任务相关、被附件 ID 引用和近期使用的图片。

摘要请求在本地视觉和传输预算内加入旧区域中的原生图片，一次请求同时处理文字与图片。摘要保留任务相关视觉事实和附件引用。未提供给摘要模型、明确不支持视觉或超出预算的图片标记为 `unparsed image`，不能将图片引用当作视觉观察。

摘要及检查点保存失败时保留原历史。成功移出上下文的图片可按附件 ID 再次读取；重新发送的图片仍消耗视觉上下文。摘要不能保证保存全部像素细节，需要精确核对时应重新看图。

## 用量显示

CLI 和 Desktop 显示一致的已提交上下文读数。压缩生成、检查和保存期间显示原读数及阶段；保存成功后更新。失败则显示回滚后的状态。自动压缩阈值与当前用量分开标注。
